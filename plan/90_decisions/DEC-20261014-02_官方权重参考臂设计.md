# DEC-20261014-02 官方权重参考臂（external_reference）设计

日期：2026-10-14 ｜ 状态：已实施（协议定义、运行时分支、准入与汇总分离）｜ 关联：`benchmarks/reference_arm_official_v1/`、`scripts/create_reference_arm_protocol.py`、`scripts/record_reference_admission.py`、`scripts/aggregate_reference_arm.py`

## 背景与问题

冻结的 1,500 槽矩阵要求每个 YOPO 权重都能声明三件事：**从随机初始化训练**、**逐轮审计**、**验证集选优**且字节与审计一致（`verify_formal_yopo_checkpoint`）。官方发布的 epoch50 是上游预训练物：能加载（7 键 rename-only 映射版用同一条 `torch.load(..., strict=True)` 正常加载），但**这三点在结构上都不成立**，因此被来源断言拒于主链之外——官方与自训练的同链同判据对比因此缺失（此前只有链外的原生 A/B，n=5）。

## 决策

新建一个**参考臂**（reference arm）协议与运行通道，让官方权重以独立来源类别进入**同一条 ROS2/Isaac 链、同一批任务与判据**，样本量与矩阵一致（每格 n=30），但：

1. **独立协议**：`benchmarks/reference_arm_official_v1/protocol.json`（300 槽 = 20 图 × 3 trial × 5 速度；模型名 `yopo_official_reference` → 后端 `yopo_reference`）。地图文件逐字节复制并校验 sha256；主协议与主准入记录不改动。
2. **来源类别 `external_reference`**：断言的对象从「训练来源/选优」改为「**字节身份**」——权重 sha256 必须等于参考协议 `reference_weights.staged_sha256`，且 `PROVENANCE.json` 与映射记录一致（`rename_only=true`）。不声明随机初始化、不声明验证集选优；对应字段写明 "NO from-scratch initialization claim and NO validation-selection claim"。
3. **独立准入**：`record_reference_admission.py` 按主准入同款两阶段 bootstrap（A：开发场景 + 参考权重；B：2 个真实参考 episode），写入参考目录的 `runtime_validation.json`（`validated_backends=['yopo_reference']`）。
4. **独立汇总**：`aggregate_reference_arm.py` 只扫 `scope=reference_arm_official_v1` 的飞行，写 `artifacts/benchmark_summary/reference_arm_official_v1_summary.json`；主聚合器按 scope 天然忽略这些运行，主 summary 1,500 槽的声明不变。
5. **运行时改动为「默认关闭」的增量子分支**：`task_spec`（新模型分支 + `verify_reference_weights`）、`run_ros2_navigation`（参考 episode 路径）、`serve_planner`/`main_planner`（`provenance_class` 参数）、`run_benchmark_matrix`（设备映射）、`validate_ros2_flight`（参考身份分支）。主路径行为不变；因运行时文件受准入哈希约束，改动以 `runtime_files_amendment_reference_arm` 透明记录（见 `benchmarks/protocol_v1/runtime_validation.json`）。

## 明确不做的事

- 不改动主协议、主准入的 `validated_backends` 与 `status`，不重跑主矩阵、不新增主矩阵重复尝试。
- 参考臂结果**永不**进入 `summary.json` / 终审 / 活动矩阵的任何计数或声明。
- 不为 MPPI、DAgger 开绿灯；如需，另行立项。

## 风险与边界

- 参考臂回答的是「官方发布权重在这条链与这些任务上的表现」，**不是**「官方训练方法复现」；叙述时必须写清来源类别。
- 参考臂同样受 Isaac/ROS2 链的物理、判据与场景生成器限制（差异 D1–D11）。
- 若上游权重文件发生变化，参考协议与准入都要重新生成（哈希锁死会显式报错）。

## 实施中发现的两个运行前置（已修复，写在这里供迁移参考）

1. **ROS2 overlay 缺失**：新根只带 `ros2_ws/src`，容器 entrypoint 仅在 `ros2_ws/install/setup.bash` 存在时才 source 它；未构建时容器里 `yopo_runtime` 无法导入（规划器启动即崩）。修复：容器内 `colcon build --merge-install --packages-up-to yopo_runtime`（`ros2_ws/install/` 已被 gitignore）。
2. **junction 不可穿越**：`checkpoints/official_epoch50_reference` 与 `artifacts/ros2_flights` 原本是指向旧根的 junction；Docker bind mount 不穿越 junction，容器既读不到官方权重、也看不到 run 目录（serve_planner 的目录检查失败 → DDS 发现超时）。修复：两处实体化为真实目录；历史飞行证据保留在旧根归档（`artifacts/ros2_flights/.archive_location.txt` 记录位置），主聚合器新增 `--allow-regression` 护栏防止空存储静默覆盖既有 summary。
