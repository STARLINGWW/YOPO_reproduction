# DEC-20261012-01：新根重构采用「运行层保留 + 工作区视图」

日期：2026-10-12 ｜ 状态：已采纳 ｜ 关联：[02_new_root_refactor_plan.md](../00_charter/02_new_root_refactor_plan.md)

## 背景

需求要求把项目重新组织为 plan / implement / report 三大区，并让 implement 成为可读的“代码工作区”。v1 主计划保留了“不物理移动代码”的约束，理由是脚本根路径解析、Docker `/workspace` 挂载和冻结证据哈希都依赖既有相对位置。

## 决策

1. 代码真实文件保持在项目根（src/scripts/configs/docker/ros2_ws/tests/external/benchmarks/vendor/assets）。
2. `implement/workspace/` 提供代码工作区**视图**：Windows 用 junction，Ubuntu/Linux 用 `bootstrap_links.sh` 生成符号链接；视图不作为 git 内容。
3. 新增/修改内容一律放在三大区；运行命令仍从项目根执行。

## 依据（本次实测）

- 容器挂载不穿越 Windows junction：`docker run -v <含 junction 的目录>:/t` 时容器内看不到 junction 目标；把代码移入 implement 并用根链接指回会破坏 Docker 训练/闭环。
- `benchmarks/protocol_v1/runtime_validation.json` 冻结了 20 个运行文件的路径与哈希；移动文件会让证据链失效。
- 脚本使用 `ROOT=Path(__file__).resolve().parents[N]` 解析项目根，物理迁移需要全量改造，风险与收益不成比例。

## 影响

- 可读性目标由“视图 + 模块地图 + 编号文档”达成；迁移时文件路径不变，Docker 与证据链不受影响。
- 代价：人在 implement 中看到的是链接；新增文件需写到根目录（约定写在 implement/99_workspace_rules）。
