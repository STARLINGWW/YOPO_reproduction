# 演示程序与权重飞行验证命令

更新：2026-10-08。本文提供查看已有成果、重新验证三个基础模型、比较聚合微调权重、官方权重演示、基线演示及结果检查的命令。所有新演示与原1800槽矩阵分开，碰撞和超时照实显示。

**最快的使用方式：先看已有seed0视频，再运行一次ROS2 seed0演示，随后在相同条件下运行seed1/seed2。要验证DAgger，用原生main演示链与基础seed0配对比较。**

当前入口均采用headless运行，然后回放飞行日志；没有可用的`--gui`参数。`-OpenVideo`在视频生成后打开系统播放器，不是实时Isaac窗口。

## 1. 两条飞行链与支持的模型

| 模型 | 权重 | 正式ROS2运行链 | 原生演示链 |
|---|---|---|---|
| seed0 | `checkpoints/formal_main_v1_seed0/best_policy.pth`，最佳epoch50 | 支持，建议首选 | main适配器支持 |
| seed1 | `checkpoints/formal_main_v1_seed1/best_policy.pth`，最佳epoch47 | 支持 | main适配器支持 |
| seed2 | `checkpoints/formal_main_v1_seed2/best_policy.pth`，最佳epoch50 | 支持 | main适配器支持 |
| dagger | `checkpoints/dagger_main_v1_seed0/best_policy.pth`，10轮微调 | 当前规划器来源检查拒绝，不能直接加载 | main适配器支持；尚需新飞行验证收益 |
| official | `external/audit_sources/YOPO-Simple/YOPO/saved/YOPO_1/epoch50.pth` | 当前规划器来源检查拒绝 | 官方Simple适配器支持 |

ROS2链使用统一0.98kg PhysX机体、完整程序化森林、标准轨迹接口和延迟检查；原生链使用Crazyflie控制/资产，其forest选项取程序化森林的树干，但不加入正式场景的低矮灌木。两条链的机体、场景、终点判据和延迟口径不同，不能直接合并成功率。

官方Simple和本地main的原语、配置及解码语义也不同。同场景比较应明确运行栈，跨栈键名转换不等于两套规划语义相同。

在PowerShell中执行。`$isaacPython`使用已有Isaac环境，演示入口不会安装或修改依赖。

```powershell
Set-Location 'D:\_AAA_CODE_ALL\Tech_reproduction\YOPO_reproduction'
$isaacPython = 'D:\_AAA_FILE_ALL\Anaconda_file\Anaconda_env\isaac61\python.exe'
Test-Path -LiteralPath $isaacPython
python scripts/queue_status.py --json
nvidia-smi
```

ROS2飞行还需要Docker Desktop的Linux engine及项目镜像：

```powershell
docker info --format '{{.OSType}}'
docker image inspect yopo-repro:train-cu128-jammy --format '{{.Id}}'
```

本次检查时Docker engine不可连接，因此没有启动新的ROS2飞行。启动Docker后上述第一条应输出linux。原生飞行不要求Docker，但会占用GPU；所有重任务串行，避免与训练、采集或其他飞行同时运行。初始化可能耗时，查看持续日志与最终metrics，不能只凭窗口关闭或exit0判定成功。

## 4. 推荐入口：一条命令运行并查看模型飞行

新增[scripts/demo_flight.ps1](../../scripts/demo_flight.ps1)把选权重、飞行、渲染、指标和打开视频连接起来。它为每次新飞行生成不同目录，核查基础模型审计哈希，在新演示中核对metrics记录的权重SHA256。视频还需完成manifest，部分MP4不能当作渲染成功。

先只打印计划，不运行仿真、不写飞行结果：

```powershell
./scripts/demo_flight.ps1 -Model seed0 -Mode ros2 -Speed 2 -MapSeed 3000 -Duration 120 -DryRun
```

正式ROS2链查看seed0：

```powershell
./scripts/demo_flight.ps1 -Model seed0 -Mode ros2 -Speed 2 -MapSeed 3000 -Duration 120 -OpenVideo
```

相同地图、速度、时长检查另外两个模型，按顺序运行：

```powershell
./scripts/demo_flight.ps1 -Model seed1 -Mode ros2 -Speed 2 -MapSeed 3000 -Duration 120 -OpenVideo
./scripts/demo_flight.ps1 -Model seed2 -Mode ros2 -Speed 2 -MapSeed 3000 -Duration 120 -OpenVideo
```

运行后终端输出指标、METRICS绝对路径和VIDEO绝对路径。新输出位于：

- `artifacts/ros2_flights/view_ros2_<model>_<timestamp>_<suffix>/`：metrics、flight.npz/csv、规划事件等。
- `artifacts/ros2_showcase/<run>_view_<timestamp>/`：global_trajectory.mp4、全局图片及render_manifest。

120秒是仿真时间上限，不是预计墙钟耗时，也不保证模型成功。正式模型展示保留局部绕行、超时和失败结果。

### 速度阶梯与不同地图

先确认低速效果，再提高速度。此处是独立开发演示，不是重跑固定基准：

```powershell
foreach ($speed in 2,4,6) {
    ./scripts/demo_flight.ps1 -Model seed0 -Mode ros2 -Speed $speed -MapSeed 3000 -Duration 120
}
```

可以更换MapSeed；固定起终点可能因地图障碍过近被拒绝，这是场景准入检查，不应改写成模型失败。脚本不接受直接改变原正式episode的任务参数。

### 现有官方入口

既有[scripts/run_final_showcase.ps1](../../scripts/run_final_showcase.ps1)也支持三个审计基础模型，自动飞行、渲染并记录审计哈希：

```powershell
./scripts/run_final_showcase.ps1 -Seed 0 -Speed 2 -MapSeed 3000 -Duration 120 -Tag view
./scripts/run_final_showcase.ps1 -Seed 1 -Speed 2 -MapSeed 3000 -Duration 120 -Tag view
./scripts/run_final_showcase.ps1 -Seed 2 -Speed 2 -MapSeed 3000 -Duration 120 -Tag view
```

该入口本身不打开播放器。成功时打印SHOWCASE_DONE；输出目录为showcase_<RunPrefix>_seed<Seed>_<timestamp>_<Tag>。它要求50轮基础训练审计，不能用于10轮DAgger模型。

## 5. 验证DAgger：和基础seed0使用同一原生main链

当前冻结ROS2 MainPlanner要求scratch来源manifest，DAgger的fine-tuned来源会被拒绝。无需改动正式运行时即可用原生main适配器检查微调模型。

先生成命令计划：

```powershell
./scripts/demo_flight.ps1 -Model dagger -Mode native -Scene forest -MapSeed 5002 -Speed 2 -Duration 120 -DryRun
```

在完全相同原生场景和运行栈下，先基础seed0，再DAgger：

```powershell
./scripts/demo_flight.ps1 -Model seed0 -Mode native -Scene forest -MapSeed 5002 -Speed 2 -Duration 120 -OpenVideo
./scripts/demo_flight.ps1 -Model dagger -Mode native -Scene forest -MapSeed 5002 -Speed 2 -Duration 120 -OpenVideo
```

这两次可以初步比较效果，但不是正式ROS2矩阵的性能结论；每条件一次也不能证明微调可靠性提升。原生链使用当前宿主PyTorch，版本不同于历史训练容器，其计时和数值结果要单独记录。

原生输出位于`artifacts/navigation/<run>/metrics.json|flight.npz|flight.csv`，视频在`artifacts/showcase/<run>/yopo_global_flight.mp4`，曲线为trajectory_metrics.png。

原生单次入口还支持任意兼容main布局的权重。例如查看中间检查点（不要标为最终best）：

```powershell
$run = 'intermediate_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/run_navigation.py --run $run --planner main --weights checkpoints/formal_main_v1_seed0/policy_epoch_010.pth --scene forest --seed 5002 --speed 2 --duration 120 --label 'local seed0 epoch10 intermediate'
& $isaacPython scripts/render_flight.py --run $run
Start-Process -FilePath (Join-Path $PWD ('artifacts/showcase/' + $run + '/yopo_global_flight.mp4'))
```

单次脚本的Isaac关闭可能遮蔽异常退出码；应检查metrics终态和render_manifest。推荐入口已连接这些检查。

```powershell
./scripts/demo_flight.ps1 -Model official -Mode native -Scene grid -MapSeed 7 -Speed 1.5 -Duration 120 -OpenVideo
```

官方原生发布栈与本地训练栈，同一个森林场景：

```powershell
$run = 'official_main_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
```

## 7. 四臂批量对照的现有入口

[scripts/run_weights_ab_batch.py](../../scripts/run_weights_ab_batch.py)提供simple_official、simple_local、main_official、main_local四个臂，默认本地模型为seed0，不支持通过参数任意换成seed1或DAgger。

打印36格的命令计划，不起飞：

```powershell
& $isaacPython scripts/run_weights_ab_batch.py --scenes 5002,5004,5001 --speeds 2,4,6 --duration 120 --dry-run
```

查看已有结果：

```powershell
$batch = Get-Content -LiteralPath 'artifacts/weights_ab_demo/batch_summary.json' -Raw -Encoding utf8 | ConvertFrom-Json
$batch.records | Select-Object arm,scene_seed,speed_mps,status,arrival_time_s,path_length_m,tracking_rmse_m | Format-Table -AutoSize
```

另一个[scripts/run_weights_ab_demo.py](../../scripts/run_weights_ab_demo.py)是历史尝试入口，默认包含official。当前冻结ROS2规划器会拒绝官方来源，而且该脚本即使dry-run也会准备官方参考目录并写派生文件；**不推荐用它执行默认官方A/B**。使用本页原生对照命令，也不要伪造scratch初始化来绕过检查。

## 8. 已有飞行只做回放，不重新起飞

ROS2日志回放只需要CPU绘图，不需要启动Docker或Isaac仿真。推荐入口的RenderOnly忽略Model所选权重，使用原飞行记录的来源。

```powershell
./scripts/demo_flight.ps1 -Mode ros2 -RenderOnly -RunName showcase_formal_main_v1_seed0_20260926_014921 -OpenVideo
```

底层等价命令，输出标签每次不同：

```powershell
$tag = 'view_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/render_ros2_flight.py --run showcase_formal_main_v1_seed0_20260926_014921 --output-tag $tag
```

正式主矩阵成功或失败任务同样可以回放；不要传episode-id再次飞行来查看旧结果。例如：

```powershell
$tag = 'view_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/render_ros2_flight.py --run primary_yopo_seed0_sparse_v33_s10_t03 --output-tag $tag
```

原生旧飞行重渲染使用[scripts/render_flight.py](../../scripts/render_flight.py)，它会启动Isaac渲染器，底层会写回同名showcase目录；推荐RenderOnly入口若已有视频则直接使用已有视频，不覆盖：

```powershell
./scripts/demo_flight.ps1 -Mode native -RenderOnly -RunName wab_seed0_s7_v4 -OpenVideo
```

两类日志格式不同：ros2_flights配render_ros2_flight；navigation配render_flight，不能交叉使用。render_flight的`--preview-only`只生成预览，不生成完整新视频。

## 9. 深入验证：实际权重身份和飞行指标

推荐入口核对基础权重审计和运行记录哈希。手工核对seed0：

```powershell
$actual = (Get-FileHash -LiteralPath 'checkpoints/formal_main_v1_seed0/best_policy.pth' -Algorithm SHA256).Hash.ToLower()
$audit = Get-Content -LiteralPath 'checkpoints/formal_main_v1_seed0/training_audit.json' -Raw -Encoding utf8 | ConvertFrom-Json
$actual -eq $audit.selection.best_policy_file_sha256
```

查看已有最终飞行（把路径替换为本次终端打印的metrics即可查看新结果）：

```powershell
$metricPath = 'artifacts/ros2_flights/showcase_formal_main_v1_seed0_20260926_014921/metrics.json'
$m = Get-Content -LiteralPath $metricPath -Raw -Encoding utf8 | ConvertFrom-Json
$m | Select-Object status,checkpoint_sha256,path_length_m,min_net_clearance_m,goal_error_m,tracking_rmse_m,max_speed_mps,real_time_factor
$m.checkpoint_sha256 -eq $actual
```

关注status、碰撞/净空、终点误差、跟踪误差、航迹长度、最大速度、实时因子和延迟；成功意味着该次判据通过，不等于所有场景成功。视频播放倍率不是实时因子。

底层ROS2新飞行完成后，还可以独立复算（以下示例引用已有飞行，运行会在该目录写入validation/evaluation派生文件）：

```powershell
& $isaacPython scripts/validate_ros2_flight.py --run showcase_formal_main_v1_seed0_20260926_014921
& $isaacPython scripts/evaluate_ros2_flight.py --run showcase_formal_main_v1_seed0_20260926_014921
```

仅观看旧成果不需要重跑上面两条。原生[validate_result.py](../../scripts/validate_result.py)要求status=success和旧终点标准，timeout/collision会按设计不通过；失败仍可由render_flight回放，不能因此删除失败记录。

## 10. 基线与诊断程序

### Agile / TopoTraj开发飞行

需要Docker。使用新run，不指定正式episode-id；这些程序验证基线，不验证YOPO权重。

```powershell
$run = 'view_agile_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/run_ros2_navigation.py --run $run --backend agile --device cuda --map-seed 3000 --speed 2 --duration 120 --scope baseline_demo_not_matrix
& $isaacPython scripts/render_ros2_flight.py --run $run --output-tag view

$run = 'view_topotraj_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/run_ros2_navigation.py --run $run --backend topotraj --device cpu --map-seed 3000 --speed 2 --duration 120 --scope baseline_demo_not_matrix
& $isaacPython scripts/render_ros2_flight.py --run $run --output-tag view
```

### 规划接口探针

以下CPU探针验证正式seed0的记录观测到ROS2轨迹输出，不产生真实飞行或视频：

```powershell
$probeOutput = 'artifacts/environment/' + 'trained_ros2_node_demo_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff') + '.json'
docker compose --profile training run --rm train python3 scripts/ros2/probe_trained_ros2_node.py --checkpoint checkpoints/formal_main_v1_seed0/best_policy.pth --dataset datasets/smoke_v1/shards/002 --output $probeOutput
```

### 空场控制与深度检查

```powershell
$probeRun = 'physx_view_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
& $isaacPython scripts/probe_highspeed_physics.py --run $probeRun
```

此程序用规定圆轨迹检查0/2/4/6/8/10m/s的控制跟踪，输出result和各速度npy；没有YOPO网络、没有避障，不生成飞行展示视频。

`probe_isaac_depth.py`查看静态深度采集与网络输入，`probe_yopo.py`验证官方模型计算链，`probe_quad_cpu.py`是CPU动力学近似。它们的默认输出为固定诊断路径，运行可能更新已有探针结果；不要把它们当作审计权重闭环证据。

## 12. 常见问题与本次验证范围

- Docker管道不存在：启动Docker Linux engine，再运行ROS2；已有回放与原生链不要求同样的Docker条件。
- Checkpoint lacks scratch initialization provenance：选了官方或微调来源进入冻结ROS2 MainPlanner。改用明确的原生演示模式，不改来源标签。
- Run already exists：新飞行用新RunName；看旧飞行用RenderOnly。
- 默认飞到旧smoke权重：直接调用run_ros2_navigation必须显式checkpoint；推荐入口已经指定。
- 渲染器退出0却没有完整视频：检查render_manifest和render_failure；推荐入口拒绝没有完成清单的部分MP4。
- timeout：只是该次未满足终点条件，视频仍可生成；不要当成程序必然崩溃，也不要冒充success。

本次完成了Markdown转换、权重哈希和8种支持组合的dry-run检查、程序/文档命令语法与链接检查。另实测了原生旧视频复用、最终ROS2飞行日志的CPU重新回放，以及本地权重曲线来源标注；没有启动新的飞行。ROS2新飞行受当前Docker未启动影响；DAgger原生模式的新增飞行效果须执行相应命令才能获得。已有视频和历史结果可直接查看。整体项目仍为1500/1800，MPPI缺口不因演示手册完善而关闭。
