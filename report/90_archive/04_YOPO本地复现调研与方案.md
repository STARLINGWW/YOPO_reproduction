## 4. 应保留的算法主链

```text
离线训练：
随机地图 → 深度图 + 相机位姿 + 地图点云
                          ↓
                    ESDF/距离场
                          ↓
深度图 + 速度/加速度/目标 → 网络 → 候选终端状态 → 多项式轨迹
                          ↑                     ↓
                     梯度回传 ← 平滑/安全/目标等代价

在线导航：
深度图 + 状态估计 + 目标 → 网络 → 按预测代价选轨迹 → 控制器 → 动力学
```

关键边界：地图用于训练代价与离线评价；在线网络不应偷偷读取真实障碍物位置。仍然需要里程计、姿态和目标输入，不能把 YOPO 解释成仅凭图像完成定位、规划与底层控制的整个飞行系统。

对已检查的 Simple 代码，网络预测正的代价值并取 **argmin**；训练用五次多项式表示和四项代价，代价监督标签 `detach` 后再计算 Smooth L1。这些实现细节应以所固定版本为准。参考 [网络](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/policy/yopo_network.py)、[训练器](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/policy/yopo_trainer.py)、[损失](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/loss/loss_function.py)。

## 5. 当前采用的 Windows 架构

| 层 | 保留/替换方式 | 状态 |
|---|---|---|
| 网络与原语 | 官方 Simple Python/PyTorch 源码与官方权重 | 本机已验证 |
| 多项式与损失 | 保留五次多项式、ESDF查询、平滑/安全/目标/加速度代价与代价监督 | 人工小地图反向传播已验证 |
| 图像/地图数据 | 使用 Isaac 场景生成器和深度传感器；导出官方兼容格式 | 静态接口检查；正式采集器待实现 |
| 状态接口 | Python数组/结构体直接传递位置、速度、姿态、目标与时间戳 | 待动态对接 |
| 仿真控制 | 复用已有Crazyflie几何控制、角速度环和PhysX模型 | 原项目存在；YOPO闭环适配待实现 |
| 可视化与评测 | Isaac画面、Matplotlib、CSV/JSON/NPZ与视频 | 需新增YOPO任务复位和评测入口 |

这不是直接运行 `test_yopo_ros.py`。它的预处理、选轨迹、轨迹求解和参考状态逻辑需要提取到无ROS适配层，替换订阅器、Publisher与Timer。不要通过在Windows临时安装`rospy`来试图解决整个ROS系统依赖。

环境分为两个进程/用途：`isaac61` 负责仿真、采集与验证；后续独立 `yopo-win` 负责正式训练。先采集并退出Isaac，再训练；训练结束后加载检查点做仿真，可减少32GB主机内存压力。初期小数据训练也可用当前已通过验证的isaac61底层Python，但不启动SimulationApp。

官方 requirements 固定torch2.4.1+cu118等旧依赖，不能覆盖当前Blackwell可用环境。实测torch2.11.0+cu128、Python3.12可运行官方核心。单独新建环境的安装组合仍须按执行手册验收。[上游依赖](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/requirements.txt)、[PyTorch Blackwell说明](https://pytorch.org/blog/pytorch-2-7/)。

本路线无需新装nvcc、Visual Studio CUDA编译链、Flightmare、Unity、ROS或容器。只有以后决定移植官方C++传感器或开发自定义CUDA扩展，才重新评估编译链。

## 6. 必須纳入实施的源码级问题

| 问题 | 已核查证据 | 处理 |
|---|---|---|
| 数据生成会删目录 | `prepareSavePath()` 对已有路径调用 `fs::remove_all` | 每个数据版本用全新绝对路径；入口遇到已存在目录直接失败，不允许静默清空 |
| 训练/验证共享地图 | `yopo_dataset.py` 在每张图内 `train_test_split` | 保留默认验证作可对照日志；额外建立完全独立地图测试集 |
| 验证状态仍随机 | `__getitem__` 每次重新采样速度、加速度、目标 | 单独冻结测试状态清单，固定随机种子与输入，避免评测抖动 |
| 地图种子不等于数据完全可复现 | 地图使用 seed+map_i；位姿 RNG 用 `random_device` | 将位姿随机种子显式配置并记录；保存数据清单和哈希 |
| 默认“到达”较宽 | 在线脚本距离目标小于 5 m 打印 Arrive | 指标脚本独立定义阈值；报告同时保留原脚本条件和更严格条件 |
| 内置分段计时不充分 | 某些 CUDA 同步被注释 | 网络用 CUDA Events 或同步计时；整体用传感器到控制输出的墙钟时间 |
| 多地图 ESDF 与局部裁剪 | `safety_loss.py` 创建 GPU 地图并按 batch 裁剪/堆叠 | 记录完整训练显存；超限先减 batch/地图批次，不据模型大小推断总内存 |
| 原控制方式与自有位置控制器不同 | 官方脚本含两种规划起点逻辑 | 原生适配器明确选择基于参考状态或实测状态；先与已验证位置控制器匹配，再比较两种策略 |

依据：[数据生成器](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/Simulator/src/src/dataset_generator.cpp)、[数据加载器](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/policy/yopo_dataset.py)、[在线节点](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/test_yopo_ros.py)、[安全损失](https://github.com/TJU-Aerial-Robotics/YOPO/blob/bd8a7f91953cfef9f1aa9a48d7ff0ab7bceee132/YOPO/loss/safety_loss.py)。

网络侧深度应为归一化数值，原始仿真 32FC1 单位是米；实感相机 16UC1 通常为毫米，而离线 PNG 是深度/20×65535。这三者不能互换。传感器为 160×90，网络 resize 到 160×96，需保存原始内参与预处理方式；不要把目标尺寸变更理解为随意改变相机 FOV。

## 7. Windows 路线的完整实施顺序

| 阶段 | 工作 | 验收产物 | 工程预算 |
|---|---|---|---|
| P0 核心检查 | 官方权重、形状、GPU前向/反向 | probe_result.json；已通过 | 已完成 |
| P1 深度适配 | 平墙验证、相机内参、深度单位、深度→网络 | 深度图/NPY/预处理对照、静态推理输出 | 0.5–1天 |
| P2 原生低速闭环 | 移除ROS接口，接轨迹参考、现有控制器和动力学 | 1–2m/s简单障碍场景、至少20次任务、失败回放 | 2–4天 |
| P3 数据生成与小训练 | 新场景、姿态采样、兼容PNG/CSV/PLY；2×1000样本训练3轮 | 配对检查、loss有限、自训权重可加载 | 1–2天 |
| P4 正式训练 | 10×10000样本、50轮、batch16、3种子 | 模型/日志/配置/数据哈希，独立测试地图 | 1–2天工程+计算时间 |
| P5 定量评测 | 地图复位、碰撞判断、成功/超时、速度/密度/噪声矩阵 | CSV/JSON、置信区间、延迟曲线、失败视频 | 2–4天 |
| P6 拓展 | 更高速度、YOPO-MINCO或更复杂平台 | 单独配置与对照，不混入Simple主结果 | 可选3–7天 |

**主要方法复现预算约7–12个工作日，日历约2–3周。** 原生接口开发会多于直接跑官方Linux演示，但你已有Isaac/Crazyflie基础，可以复用控制与动力学。进度以验收项为准，不能承诺日期。

P2先用宽间距柱子/方块，目标10–20m，速度1m/s再2m/s。暂时不要把Crazyflie提高到6m/s；4/6m/s评测可先在具有相应推力/加速度裕量的通用四旋翼模型进行。必须同时报告飞机模型和控制器。

P3数据契约保持官方加载器要求：每张地图目录`0/`、`1/`…，文件名采用`img_0.png`等带下划线和数字索引的格式；根目录对应`pose-0.csv`、`pointcloud-0.ply`。位姿CSV有表头，列依次位置xyz、四元数wxyz；PNG为uint16，数值=clip(depth_m/20,0,1)×65535。训练阶段resize到160×96。

地图真实几何、深度渲染与PLY必须来自同一场景描述；采样位姿应在自由空间并有净空。随机种子、相机外参、单位和地图ID必须落盘。数据生成器只创建新目录，拒绝覆写已有目录。

新增采集器先做100帧，再做2000样本，再扩至10万；每次扩容前检查PNG数量、CSV行数、图像与姿态索引、随机重投影和ESDF距离。不要先生成巨量错误数据。

已提供 `scripts/train_windows.py`：支持dataset/epochs/batch/workers/seed/save_interval，默认从头训练，输出到本项目checkpoints，保留上游训练算法。入口已做参数检查，但完整数据训练尚未执行。它保留上游同地图训练/验证切分，独立地图评测必须另做。周期保存网络权重，训练结束另存优化器与RNG状态；尚未实现中断后的恢复CLI。

Windows DataLoader初次采用workers=0；验证后比较2/4。代码必须保留`if __name__ == '__main__'`，避免spawn重复运行主流程。首轮FP32；混合精度、TensorRT只在基线完成后再评估。

| 磁盘 | 预留 40–80 GB；独立训练环境约10–20GB，数据/检查点/缓存约10–30GB，视频按需扩展；已有Isaac环境不重复安装 |
| 十万张深度图 | 160×90×2×100000≈2.88 GB 未压缩像素；PNG 压缩后依场景而变，另加点云/位姿/元数据 |
| ESDF | 按 60×60×约21 m、0.2 m 体素，约 9.45M 格/地图；float32 约 36 MiB/张，十张约 360 MiB，仅为基础距离张量 |
| ESDF 峰值 | 点云、CPU float64 距离变换、临时张量、batch 裁剪和网络都会增加内存；实测峰值后再扩大地图 |
| 主机内存 | 释放应用后争取16GB以上可用；Isaac采集/闭环与正式训练串行运行 |
| 显存 | 建议正式训练前争取留出至少 8 GB；先测 batch16，再决定是否扩大，OOM 可降到8/4 |
| DataLoader | Windows先workers=0，再测试2/4；不要直接使用全部28线程 |
| 数据生成时间 | 原生Isaac正式采集未测；10万帧先预算1–6小时，必须实测1000帧后更新，不套用官方CUDA生成器速度 |
| 单次正式训练时间 | 首次预留 2–8 小时窗口；3个种子预留 6–24 GPU小时；用前两轮完整epoch计时修正 |

官方 Simple README 报告 3080+i9-12900K 上十万样本训练50轮少于1小时，但不能直接当作本机承诺；软件版本、DataLoader、磁盘IO 和地图配置都会影响结果。[官方运行说明](https://github.com/TJU-Aerial-Robotics/YOPO/tree/YOPO-Simple)。

实际估算采用 `剩余epoch数 × (完整训练epoch耗时 + 验证耗时) + 检查点/日志开销`；不把探针的24.69ms机械外推为完整训练时间。若每个完整epoch需要10分钟，应按约8小时预算，先定位IO/CPU瓶颈再考虑硬件。

当前32 GB内存可以开始，不建议立刻升级。只有实测持续交换、需要同时跑 Isaac 与训练，或扩大多地图 ESDF 后，再评估64 GB。单机主线不需要多GPU。

## 9. 评测设计：怎样证明主要复现完成

**所有阈值在看测试结果前固定。** 初期工程验收可设：简单独立场景、2 m/s下20次任务至少18次成功，无NaN或节点故障。它只用于判断能否进入下一阶段，不代表论文指标。

最终测试建议：每种条件至少30条固定任务，所有模型使用同一份任务清单；地图种子与训练集完全分离。3种训练种子分别报告，并汇总均值、离散程度与成功率95% Wilson区间。

| 维度 | 推荐设置 |
|---|---|
| 场景 | 林地为主；墙面/柱子作扩展；不同生成机制的洞穴可做域外测试 |
| 速度 | 主矩阵 2/4/6 m/s；8/10 m/s 单列为超出给定6m/s训练设置的压力测试 |
| 密度 | 至少稀疏、较密两档；保存真实障碍生成参数，不将树间距直接当作论文密度 |
| 噪声 | 干净深度、约2cm/5cm噪声、5%/10%缺测；为自定义鲁棒性实验 |
| 延迟 | 额外0/33/66ms观察延迟；明确采用实时时间或仿真时间 |
| 成功定义 | 达目标半径例如1m内且速度低于0.5m/s持续1s，途中无碰撞；另报告官方5m到达口径 |
| 超时 | 例如 `max(30s, 3×直线距离/目标速度)`，起始前写入配置 |
| 碰撞定义 | 膨胀障碍物/机体包络后做几何检查；控制仿真穿过点云不等于“无碰撞” |

指标：成功/碰撞/超时次数，最小与平均障碍距离，飞行时间、路径长度与长度比，跟踪误差，速度/加速度/jerk、控制饱和，网络P50/P95/P99、感知到指令总延迟、掉帧率、实时因子、GPU/CPU峰值资源。安全代价中的 `r=0.6` 是代价尺度，不能直接充当飞机碰撞半径。

基线依次做：官方预训练、自己训练、固定原语按真实代价挑选的诊断上界、相同终端状态/代价下的梯度优化专家。诊断上界读取真实地图，必须与可部署在线方法分开标识。最能检验 guidance learning 的是：在同一数据、同一代价与同一候选初始化下，对比网络预测和直接轨迹优化的平均/最优代价及用时。

消融建议：去掉安全项、去掉平滑项、减少候选原语、去掉状态增强；每次只变一项。改变原语数需要同步输入尺寸、网络输出与权重，不作为临时测试开关；必须重新训练并检查输出形状。

论文协议可对照原文：100K样本、50 epoch、batch16、学习率1.5e-4；专家优化、两档森林密度与不同速度的成功率实验属于不同评价层次。更高置信度的30次/条件是本方案增加的统计要求。[原论文](https://tju-air-lab.github.io/projects/YOPO/YOPO.pdf)。

最小主矩阵为2档密度×3档速度×30任务=180次/模型，3个训练模型共540次；噪声/延迟再做选定子集，避免第一轮实验组合过大。必须保留失败案例，不只输出成功视频。

## 10. 当前范围对原论文复现程度的影响

在不使用WSL/Docker的约束下，本轮定位为“YOPO核心算法复现 + Windows/Isaac仿真迁移验证”，可以包括从头训练、专家优化对比与导航成功率评测。它不是对官方Flightmare/Unity实验环境的逐项重建。

## 11. 与现有 Isaac Sim / Crazyflie / MINCO 工作的衔接

已有 `projects/01_minco_core`、`06_flatness_ctbr`、`07_cf_sysid`、`08_cf21_brushless_isaacsim` 提供轨迹、控制和动力学基础。本次直接在用户指定的 `YOPO_reproduction` 下创建YOPO适配层，将网络作为上层局部规划器接入现有仿真；把采用的控制器、模型文件复制或明确版本化引用，并让所有新结果保存在本目录。

接口契约建议：

```text
输入：depth_m[H,W]、K、时间戳、机体/相机变换、p_W/v_W/a_W/R_WB、goal_W
输出：带起始时间与持续时间的轨迹，或 p/v/a/jerk/yaw 参考值；附规划有效期
控制：由独立控制器转换为姿态/角速度/推力，再施加给仿真动力学
```

必须专门验证：

1. 相机光轴深度与沿射线距离不同；先用正对平墙的深度分布核对定义，必要时按内参转换。
2. YOPO 的机体/局部规划坐标、ROS NWU、Isaac世界坐标、光学坐标之间用显式矩阵转换；SciPy的xyzw与部分接口wxyz需逐处标记。
3. 遵循官方160×90传感器和160×96网络处理，保持FOV及无效深度处理；额外渲染分辨率不代表网络输入要增大。
4. 深度、里程计和目标对齐同一仿真时钟；记录帧龄。规划约20–30Hz作为初始目标，控制频率采用已验证控制器设置。
5. Crazyflie的质量、推力上限、响应与官方飞机不同；先在1–2m/s和宽间距障碍下验证，重新约束加速度与净空，不能直接拿6m/s轨迹视为平台可执行。
6. YOPO输出不能当作电机命令直接发送。现有控制器可复用，但每条轨迹需检查可执行性、有效期和控制饱和。

训练与Isaac渲染串行运行。在线推理优先在Isaac进程中直接调用PyTorch，避免IPC与时钟误差；若环境依赖冲突再使用本地进程通信。读取真实物理状态作为里程计真值属于第一阶段条件，后续再加入噪声和延迟。

YOPO-MINCO应在上述基线完成后比较“轨迹表达能力、窄通道成功率、平滑性、推理/训练成本”，与既有MINCO轨迹优化经验相结合；不同分支的网络权重不可互换。
